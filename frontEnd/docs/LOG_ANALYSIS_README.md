# Log Analysis Tools

This directory contains tools for analyzing and documenting the OCR parsing logs generated by the voter data extraction system.

## Files

### Documentation
- `PARSING_LOG_DOCUMENTATION.md` - Complete documentation of the parsing log structure
- `PARSING_LOG_TEMPLATE.md` - Template for documenting parsing logs
- `LOG_ANALYSIS_README.md` - This file

### Code
- `../lib/log-parser.ts` - Log parsing utility library
- `../examples/log-analysis-example.ts` - Example usage of the log parser

## Quick Start

### 1. Understanding the Log Structure

The parsing logs follow a structured format with different phases:

1. **Name Extraction** - Multiple strategies for extracting voter names
2. **House Number Extraction** - Extracting house numbers with fallbacks
3. **Age/Gender Extraction** - Extracting age and gender information
4. **Voter Matching** - Matching extracted data to individual voters

### 2. Using the Log Parser

```typescript
import { ParsingLogParser, parseLogFile, generateLogReport } from '../lib/log-parser'

// Parse a log file
const analysis = parseLogFile(logContent)

// Generate a detailed report
const report = generateLogReport(logContent)

// Export to CSV
const csv = exportLogToCSV(logContent)
```

### 3. Analyzing Your Logs

1. **Copy the console output** from your browser's developer tools
2. **Save it to a file** (e.g., `parsing-log.txt`)
3. **Use the log parser** to analyze the data
4. **Generate reports** for documentation

## Log Parser Features

### Analysis Metrics
- Total rows processed
- Total voters extracted
- Success rates for each data field (names, houses, ages, genders)
- Strategy success rates for name extraction
- Common issues encountered

### Export Formats
- **Markdown Report** - Human-readable analysis
- **CSV Export** - Machine-readable data for further analysis
- **JSON Data** - Structured data for programmatic use

### Strategy Analysis
The parser tracks which extraction strategies are most successful:
- Labeled names (most reliable)
- Unlabeled names
- Permissive extraction
- Aggressive fallback
- Segment-based extraction
- Truncated name recovery
- Desperate attempts

## Usage Examples

### Basic Analysis
```typescript
import { parseLogFile } from '../lib/log-parser'

const logContent = `[your console log here]`
const analysis = parseLogFile(logContent)

console.log(`Total voters: ${analysis.totalVoters}`)
console.log(`Name success rate: ${(analysis.extractionStats.names.successful / analysis.totalVoters * 100).toFixed(1)}%`)
```

### Generate Report
```typescript
import { generateLogReport } from '../lib/log-parser'

const report = generateLogReport(logContent)
console.log(report)
```

### Batch Processing
```typescript
import { ParsingLogParser } from '../lib/log-parser'

const logFiles = ['log1.txt', 'log2.txt', 'log3.txt']
const results = logFiles.map(file => {
  const content = fs.readFileSync(file, 'utf8')
  return new ParsingLogParser(content).getAnalysis()
})
```

## Log Structure Reference

### Name Extraction Logs
```
=== EXTRACTING NAMES ===
Content preview: [content]
Found labeled name: "[raw]" -> "[clean]"
Found [count] labeled names
=== END NAME EXTRACTION ===
```

### Row Processing Logs
```
=== Row with [count] headers ===
Headers: [header_info]
Names found: [count] [names_array]
Houses found: [count] [houses_array]
Ages/Genders found: [count] [age_gender_array]
```

### Voter Matching Logs
```
--- Processing voter [num] (Serial: [serial]) ---
Final name for voter [serial]: "[name]"
Voter [serial]: [name] or [MISSING NAME]
```

## Troubleshooting

### Common Issues
1. **Log format changes** - Update the parser if log format changes
2. **Missing data** - Check if all expected log entries are present
3. **Encoding issues** - Ensure logs are saved with UTF-8 encoding
